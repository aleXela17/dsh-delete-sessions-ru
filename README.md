# dsh-delete-sessions-ru

Добавляет в DeepSeek Harness настоящее **«удаление сессии»**: из меню «…» каждой сессии в боковой панели её можно удалить безвозвратно, а не только «архивировать».

## Зачем нужен этот плагин

Встроенное в DSH «архивирование» (archive) делает ровно одно: добавляет id сессии в набор `archivedSessionIds` и прячет её из сгруппированного интерфейса. Оно **никогда не удаляет файлы с диска** — журнал сессии (`~/.dsh/sessions/<project>/<id>/session.v4.jsonl.zstd`) и кэш проекции (`~/.dsh/storages/session_projcache/sessions/<id>.json`) остаются на диске навсегда.

Этот плагин восполняет недостающее «удаление»: останавливает текущую работу сессии → снимает архивирование/закрепление/учёт рабочего пространства → удаляет кэш проекции → удаляет каталог журнала → рассылает событие удаления, чтобы интерфейс сразу обновился.

## Установка

### Способ 1: установка как bundle (рекомендуется)

```bash
dsh plugin --profile desktop add dsh-delete-sessions-ru
```

В `cordis.patch.yml` автоматически вставится строка, загружающая плагин.

### Способ 2: ручная установка

1. Скопируйте этот каталог в `node_modules/dsh-delete-sessions-ru` профиля (или используйте зависимость `link:`).
2. Добавьте одну строку в собственный `cordis.patch.yml` этого профиля:

```yaml
- insert:
    - id: dsh-session-delete
      name: 'dsh-delete-sessions-ru'
```

> Внимание: после добавления строки вручную **не** допускайте, чтобы применялся `cordis.patch.yml` (тот, что лежит в этом каталоге), — иначе один и тот же плагин загрузится дважды из-за конфликта id.

3. Перезапустите DeepSeek Harness.

## Использование

1. Нажмите «…» у любой сессии в боковой панели.
2. В меню прямо под «Архивировать сессию» появится «Удалить сессию» (со значком удаления, в том же стиле, что и остальные пункты).
3. Нажмите и подтвердите. После удаления строка сразу исчезает из списка.

## Детали поведения

Удаление выполняется в фиксированном порядке; сбой любого шага приводит к общей ошибке — чтобы не оставалось незавершённого состояния «в интерфейсе нет, а на диске осталось»:

1. **Остановка активности** — вызывается `workspace/session-stop` (тот же путь, что у «остановить и архивировать», `agent.cancel`), с коротким ожиданием записи последнего события на диск.
2. **Снятие учёта** — `unarchiveSession` + `unpinSession` + `detachSession` по каждому рабочему пространству (все идемпотентны).
3. **Удаление кэша проекции** — через домен storage-domain `session_projcache` (память и диск синхронно); если домен не смонтирован, шаг пропускается (кэш производный и пересоздастся при следующем холодном чтении).
4. **Удаление каталога журнала** — предпочтительно через `sessionPersistence.locate()` для точного пути (id сессии безопасно закодирован, обхода пути нет), с повторами на случай кратковременной занятости файла антивирусом/индексатором в Windows.
5. **Широковещательное удаление** — `api-session/removed` уже в белом списке пересылки DSH, браузер сразу убирает строку.

## Безопасность

- Маршрут удаления принимает POST только с **loopback-источника**, тело содержит лишь один `sessionId`.
- Перед удалением id сессии проверяется на реальное существование через `sessionPersistence.stat()`.
- Путь из `locate()` кодируется собственным `encodeSegment` DSH — обхода пути нет.

## Ограничения

- Если в профиле не смонтирован домен `session_projcache` или `~/.dsh/sessions` не определяется, кэш проекции/каталог журнала могут остаться (кэш пересоздастся при следующем холодном чтении; журнал придётся чистить вручную).
- Удаление **необратимо** — подтверждайте осознанно.
